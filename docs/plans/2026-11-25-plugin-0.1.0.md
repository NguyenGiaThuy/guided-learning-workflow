# Guided Learning Plugin 0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the plugin up to the point where the owner can rehearse it: steps 1 and 2 of *Testing before release*.

**Architecture:** One Python package, `scripts/gl/`, holds all logic as plain functions on files. `scripts/learning.py` is its command line, and hooks and skills only call that. State is always computed from the project's files. Nothing in this plan touches a game project.

**Tech Stack:** Claude Code plugin (2.1.331 or later), Python 3.9+ standard library, `unittest`, Git Bash on Windows.

**Spec:** `docs/design.md`

## Global Constraints

- Python 3.9+, standard library only. Files are UTF-8, written with `\n`, and replaced atomically (temporary file, then `os.replace`). Output is UTF-8 even on a Windows console.
- Public repository: no person's name, email or real game in any file. The fake game is called *Lantern Keeper*.
- Never push. Commit on branch `build-0.1.0`. Do not change `git config`.
- The regular expression of a TODO is `TODO\(owner (\d+)\.(\d+)\)`.
- A hook that raises an exception answers `deny` (PreToolUse) or `block` (UserPromptSubmit) with the text `guided-learning error: <message>`. SessionStart, PostToolUse and Stop print it as `systemMessage` and never block.
- In a project without `.claude/learning/project.json`, every hook prints nothing and exits 0, and creates no file. `/setup-learning` is the only command that works.
- Paths are compared after `os.path.normcase(os.path.realpath(...))`.
- All user-visible text comes from `gl/texts.py`.
- Run the unit tests with `python -m unittest discover -s tests -v`. Expected at the end of every task: `OK`.

## Review Focus

1. The owner saves a script in their editor while a long tool call of the AI runs: the message must ask, not accuse, and nothing is blocked or reverted.
2. The AI edits a locked file through another spelling of its path (`..`, different case, forward slashes): refused.
3. A file written by hand with a BOM, CRLF or a trailing comma: BOM and CRLF are accepted, and bad JSON names the file and line.
4. Two chats open at once: no lost record, because each write re-reads the file under a lock file.
5. `/summarize-phase` typed as `/guided-learning:summarize-phase 2`, with extra spaces, `phase-2`, `abc`, or the number of a missing phase: the first three work as 2, the others give a clear message.

## Data

`project.json`

```json
{"docs": "Docs/learning", "code": ["src"], "extensions": [".cs"], "ownerMark": "[Explicit(\"Owner\")]",
 "suites": ["Unit"], "background": "C# web developer"}
```

`phase-N.plan.json`

```json
{"phase": 2,
 "concepts": [{"id": "ai", "name": "Enemy AI"}],
 "parts": [{"name": "Part 1", "tasks": ["Shells and tests"], "scripts": [1]}],
 "scripts": [{"id": 1, "name": "Moth", "path": "src/Moth.cs", "concept": "ai", "todos": ["1.1", "1.2"], "tests": ["MothTests.Turns"]}],
 "targets": [{"id": "wins", "text": "Average player wins", "measure": "20 bot runs", "settings": ["Moth.speed"], "min": 40, "max": 60}],
 "questions": [{"id": "q1", "concept": "ai", "text": "How does it choose a target?", "points": ["nearest", "in range"]}]}
```

`phase-N.json`: `status` (`planning`, `build`, `done`, `skipped`), `branch`, `planHash`, `changes`, `turn` (`ai` or `owner`), `part` (index), `tasksDone`, `locked`, `log`, `results` (per suite: `time`, `tests` name to `passed` or `failed`), `closing` (`pending`, `tries`), `skip`, `carried`. `tune` and `wrap-up` are computed, not stored.

`phase-N.md` headings: `## Notes for later`, `## Answers` (`### q1`), `## Concept summary` (`### <concept name>`), `## Lessons` (list items), `## Process` (`Surprised me:`, `Differently:`).

### Task 6: Hooks

**Files:** Create `hooks/hooks.json`, `scripts/gl/hooks.py`; Test `tests/test_hooks.py`

**Interfaces:**
- Produces: `hooks.handle(event, data: dict, cwd) -> dict | str | None`. `hooks.json` calls `bash "${CLAUDE_PLUGIN_ROOT}/scripts/run.sh" hook <event>` for SessionStart, UserPromptSubmit, PreToolUse (`Edit|Write|MultiEdit|NotebookEdit` refuse, `*` snapshot), PostToolUse (`*`) and Stop.
- UserPromptSubmit runs `commands.run` for the owner's commands. A failure is `{"decision": "block", "reason": text}`; success adds the text as context. Only this hook runs `start`, `approve`, `build` and `finish`.
- PreToolUse refuses: locked owner scripts; an edit that removes a TODO; `phase-N.json`, an approved `phase-N.plan.json`, `project.json`, `config.json`, everything in `local/`; the code folders from `/start-phase` until `/build-phase`. The real project is guarded in rehearsal too.
- PostToolUse compares the snapshot of this `tool_use_id`. On a difference: `systemMessage` for the owner, and for the AI the reason `Owner or workflow files changed while this tool ran: <files>. Ask the owner whether it was them before you do anything else.` Nothing is reverted.
- Stop: while `closing.pending`, block until `last_assistant_message` contains the closing text. After 3 tries, clear it and give the text as `systemMessage`.
- `learning.py log`, `record-tests` and `hand-over` change `phase-N.json` by themselves, which is not reported.

- [ ] **Step 1:** Failing tests: `no_project_is_silent_and_writes_nothing`; `session_start_line`; `start_phase_blocked`; `finish_writes_done_only_from_the_prompt`; `locked_script_refused` for Edit, Write and MultiEdit, with the four path spellings of Review Focus 2; `unlocked_file_allowed`; `todo_removal_refused_before_the_lock`; `code_refused_while_planning_and_allowed_after_build_phase`; `config_json_refused`; `real_files_guarded_in_rehearsal`; `shell_change_is_reported`; `change_by_learning_py_is_not_reported`; `exception_denies` and `exception_in_stop_does_not_block`; `stop_asks_until_present`; `stop_gives_up_after_three`.

**Interfaces:**
