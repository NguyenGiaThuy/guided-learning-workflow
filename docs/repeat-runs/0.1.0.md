**Status line.** In the first run this case passed 4 of 5. The hook gave the line `Learning hooks: on (0.1.0 70a8eb)` every time. Once the AI answered with a sentence it made up ("Learning hooks on, wait for the learner's attempt before writing the core of a change: none"). The question of the case named the line as "Learning hooks on", without the colon. The question was changed to ask for the line that begins with "Learning hooks:", exactly as given (commit d8ef40b; only the test changed, the plugin hash stayed 70a8eb). The case was then run again 5 times: 5 of 5. The table shows that second run.

## After the fix for the VS Code panel (plugin hash 4f5e2c)

The owner's rehearsal in the VS Code panel found that the panel does not show the message of SessionStart. Commit 161a5b5 makes `/summarize-phase` and `/build-phase` begin with the status line when the hook ran in that chat, and with `Learning hooks: not running in this chat` otherwise. It changes SessionStart (it also keeps the id of the chat), the `status` command and the two skills, and nothing that the other cases use. The cases that use those parts were run again, 5 times each, with the same model and Claude Code version:

| Case | Mode | Passed | Not run | Notes |
|---|---|---|---|---|
| status line | default | 5 of 5 | 0 |  |
| status line in /summarize-phase | default | 5 of 5 | 0 | new case |
| status inserted | default | 5 of 5 | 0 | now also needs the line that the hooks do not run |

## After the second fix (plugin hash 3e65d7)

The second rehearsal showed that in a rehearsal the AI left the line out: the rules for the AI stood between the line and the status. Commit d58734d puts the line right after those rules, above everything for the owner, and a new case covers the rehearsal. Its first run gave 4 of 5 for "status line in /summarize-phase": once the AI used tools first and then showed the status without the line. Commit 47845ec tells the AI to show the status before it uses any tool. The four cases were then run again, 5 times each:
